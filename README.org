#+title: piano-mode
#+options: toc:3

Turn your computer keyboard into a piano inside Emacs, with real
key-down / key-up tracking.

* Features
- *True key-up*: notes keep sounding exactly as long as you hold the
  key — no fixed note length, no auto-release.
- *Low dependency*: a single Elisp file (zero third-party Emacs
  packages) plus one small Rust binary with zero crate dependencies.
- *Linux*: works under both X11 and Wayland sessions.
- *No root, no =input= group*: the X11 key map and the kernel evdev
  ABI are both readable by the logged-in user on normal desktop
  setups.
- Chords and polyphony through one persistent FluidSynth process.

* Requirements
- GNU Emacs >= 28
- Rust toolchain (only needed to build ~piano-keys~)
- FluidSynth and a SoundFont, e.g. on Debian/Ubuntu:
  #+begin_src sh
  sudo apt install fluidsynth fluid-soundfont-gm
  #+end_src

* Install
#+begin_src sh
git clone https://github.com/tinyblinker/emacs-piano-mode
cargo build --release --manifest-path emacs-piano-mode/piano_core/Cargo.toml
install -Dm755 emacs-piano-mode/piano_core/target/release/piano-keys ~/.local/bin/piano-keys
#+end_src

#+begin_src elisp
(add-to-list 'load-path "/path/to/emacs-piano-mode")
(require 'piano-mode)
#+end_src

When the package is loaded straight from this repository (with
=eval-buffer= or =load-file=), the bundled
=piano_core/src/TimGM6mb.sf2= SoundFont is found automatically.
=piano-keys= itself must be reachable through =exec-path= (e.g.
=~/.local/bin=, as installed above) or =piano-keys-program=.

* Usage

=M-x piano-play= opens the =*piano*= buffer and starts everything.
Run =M-x piano-mode= (or kill the buffer) to stop the instrument.

#+begin_src text
  W E   T Y U   O P
A S D F G H J K L ;
#+end_src

| key | note | key | note | key | note |
|-----+------+-----+------+-----+------|
| a   | C4   | g   | G4   | k   | C5   |
| w   | C#4  | y   | G#4  | o   | C#5  |
| s   | D4   | h   | A4   | l   | D5   |
| e   | D#4  | u   | A#4  | p   | D#5  |
| d   | E4   | j   | B4   | ;   | E5   |
| f   | F4   |     |      |     |      |
| t   | F#4  |     |      |     |      |

The mapped keys are read *globally* by =piano-keys=.  While the
=*piano*= buffer has focus they do not insert text, and focus tracking
releases all notes as soon as you leave it — other buffers keep normal
typing.

* How it works

#+begin_src text
physical keyboard
      │  OS key state, polled (default 4 ms)
      ▼
piano-keys  (Rust, zero crates, no root/input group)
      │  "down A" / "up A" lines on stdout
      ▼
piano-mode.el  (key → MIDI map, note state, focus gate)
      │  "noteon 0 60 100" / "noteoff 0 60" lines on stdin
      ▼
FluidSynth  (one persistent process)
#+end_src

* Linux backends

| session  | backend          | permissions                                          |
|----------+------------------+------------------------------------------------------|
| X11      | =XQueryKeymap=   | none                                                 |
| Wayland  | kernel evdev ABI | seat access (udev =uaccess=; =input= group only as fallback) |

=piano-keys= picks the backend automatically (evdev under a Wayland
session, X11 otherwise); force one with =piano-keys-extra-args=, e.g.
=("--backend" "x11")=.

*Choosing a keyboard with several plugged in:* on the first =M-x
piano-play= the key reader lists the keyboards it can see and Emacs
asks which one to use (a single keyboard is picked automatically; the
choice is remembered for the session).  =piano-select-device= re-asks
and saves the answer to =piano-device=, so it survives restarts.

*Wayland note:* Wayland deliberately hides global keyboard state from
applications.  =piano-keys= therefore reads =/dev/input= directly,
which the logged-in user can normally read on systemd distributions
(the =uaccess= udev tag).  If your setup denies access, either add
yourself to the =input= group, or force =--backend x11= — which works
while an X11 window (e.g. an X11 Emacs build under XWayland) has
focus.

* Configuration

| variable                   | default       | meaning                              |
|----------------------------+---------------+--------------------------------------|
| =piano-keys=               | alist         | key names → MIDI notes               |
| =piano-transpose=          | 0             | semitone shift                       |
| =piano-velocity=           | 100           | MIDI velocity                        |
| =piano-keys-program=       | "piano-keys"  | key reader executable                |
| =piano-keys-extra-args=    | nil           | extra reader arguments               |
| =piano-device=             | nil           | evdev device path; nil asks interactively |
| =piano-poll-ms=            | 4             | key polling interval                 |
| =piano-synth-program=      | "fluidsynth"  | synthesizer executable               |
| =piano-soundfont=          | auto          | SoundFont path                       |
| =piano-audio-driver=       | nil           | FluidSynth audio driver              |
| =piano-gain=               | 0.5           | FluidSynth master gain               |

While the =*piano*= buffer has focus, the mapped keys do not insert
text; leaving it releases all notes.

* Troubleshooting
- *No sound at all*: run =M-x piano-doctor= — it reports the
  synthesizer, SoundFont, key reader and device access in one buffer —
  and =M-x piano-test-note= to test the synthesizer alone.
- *piano-keys not found*: build it (=cargo build --release= in
  =piano_core/=) and put =target/release/piano-keys= on =PATH=, or
  point =piano-keys-program= at the built binary.
- *The wrong keyboard plays*: run =M-x piano-select-device= to pick
  the right one, or run =piano-keys --list-devices= to see the
  candidates (stable paths live under =/dev/input/by-id/=).
- *FluidSynth not found*: install FluidSynth (e.g. =sudo apt install
  fluidsynth=).
- *=piano-keys exited (cannot list /dev/input ...)=*: the Wayland
  backend could not read keyboard devices.  See the Wayland note above.
- *FluidSynth exited at startup*: the SoundFont or the audio driver is
  unusable; the error shows FluidSynth's stderr.  Try
  =piano-audio-driver= ("pipewire", "pulseaudio", "alsa") or another
  SoundFont.
- *No sound*: run =fluidsynth -a alsa -n /path/to/font.sf2= manually
  and check the audio driver; set =piano-audio-driver=.
- *Latency*: lower =piano-poll-ms= (default 4 ms) and check
  FluidSynth's audio buffer settings.
- *Stuck note*: =M-x piano-mode= releases everything.
