#+title: piano-mode
#+options: toc:nil

Inspired by "https://github.com/defaultxr/piano-mode", turn
your computer keyboard into a piano inside Emacs, with real
key-down / key-up tracking: notes keep sounding exactly as
long as you hold a key.

* Dependencies
=piano-mode= currently supports Linux only.  The installation
examples below are for Arch Linux; users of other distributions
should install the equivalent FluidSynth, SoundFont, Rust/Cargo,
and input-permission packages with their own package manager.

- *FluidSynth* — the software synthesizer:
  #+begin_src sh
  sudo pacman -S fluidsynth
  #+end_src
- *SoundFont* — the instrument samples.  The Arch package installs
  =/usr/share/soundfonts/FluidR3_GM.sf2=, which is found
  automatically; otherwise install another =.sf2= file and set
  =piano-soundfont=:
  #+begin_src sh
  sudo pacman -S soundfont-fluid
  #+end_src
- *Cargo* — builds the bundled =piano-keys= reader on first use:
  #+begin_src sh
  sudo pacman -S rust
  #+end_src
  With rustup instead:
  #+begin_src sh
  sudo pacman -S rustup
  rustup default stable
  #+end_src
- */dev/input access* — either add your user to the =input= group
  and log out and back in:
  #+begin_src sh
  sudo usermod -aG input "$USER"
  #+end_src
  or grant the active session access with a udev rule:
  #+begin_src sh
  sudo tee /etc/udev/rules.d/99-piano-keys.rules >/dev/null <<'EOF'
  KERNEL=="event*", SUBSYSTEM=="input", ENV{ID_INPUT_KEYBOARD}=="1", TAG+="uaccess"
  EOF
  sudo udevadm control --reload-rules
  sudo udevadm trigger
  #+end_src
  Verify with =ls -l /dev/input/event*=; once built,
  =piano-keys --list-devices= lists readable keyboards.

* Install and use
With Emacs 30 or newer, install the package and start it with:

#+begin_src elisp
(use-package piano-mode
  :vc (:url "https://github.com/tinyblinker/emacs-piano-mode")
  :custom
  ;; (KEY . MIDI) pairs; add as many as you like.  Key names are
  ;; case-insensitive, so "a" and "A" are the same key.  Middle C is 60.
  (piano-keys '(("a" . 60) ("w" . 61) ("s" . 62)))
  ;; Reader executable: a name on PATH or an absolute path.
  (piano-keys-program "piano-keys")
  ;; Extra reader arguments, e.g. '("--device" "/dev/input/event3").
  (piano-keys-extra-args nil)
  ;; Build the bundled Rust reader on first use when Cargo is available.
  (piano-auto-build t)
  ;; Pin a keyboard; `M-x piano-select-device' saves a stable
  ;; /dev/input/by-id or by-path link.  Do not set this to nil here if
  ;; you use that command: it clears the saved choice.
  ;; (piano-device "/dev/input/by-id/usb-Your_Keyboard-event-kbd")
  ;; Keyboard polling interval in milliseconds.
  (piano-poll-ms 4)
  ;; Semitones added to every note.
  (piano-transpose 12)
  ;; MIDI velocity, 1-127.
  (piano-velocity 100)
  ;; FluidSynth executable.
  (piano-synth-program "fluidsynth")
  ;; SoundFont path; nil checks PIANO_SOUNDFONT and system locations.
  ;; (piano-soundfont "/usr/share/soundfonts/FluidR3_GM.sf2")
  (piano-soundfont nil)
  ;; FluidSynth audio driver; nil uses FluidSynth's default.
  (piano-audio-driver "pipewire")
  ;; FluidSynth master gain.
  (piano-gain 0.5))
#+end_src

Then run =M-x piano-play=; =M-x piano-mode= (or killing the
=*piano*= buffer) stops it.  Changing =piano-keys= takes effect
immediately, as do =piano-transpose= and =piano-velocity=.  Key
names are case-insensitive, so an uppercase layout works without
changes.  Reader options restart =piano-keys=; synthesizer options
restart FluidSynth when it is running.  =piano-device= set to a
non-nil path restarts a running reader; set it to nil only if you
want to clear the saved choice, and use =M-x piano-select-device=
to choose a device.
If an older checkout is already installed, remove
=~/.config/emacs/elpa/piano-mode= (or run =M-x package-vc-upgrade=)
and evaluate the form again.

* How it works
=piano-keys= reads raw key state from the Linux evdev ABI under
=/dev/input=, reports key-down and key-up lines to Emacs, and Emacs
maps those keys to MIDI notes and drives one persistent FluidSynth
process.  The =*piano*= buffer ignores every printable key, so
=special-mode= commands such as =g= and =q= and digit arguments
cannot fire.  Only keys present in =piano-keys= produce notes, and
events are processed only while the =*piano*= buffer is selected;
leaving it releases every sounding note.

* Configuration
The example above shows every =defcustom= in the package;
=piano-device= is commented out because setting it to nil would
clear a choice saved by =M-x piano-select-device=.  Use
=M-x customize-group RET piano RET= to see their full documentation
and current values; =:custom= in =use-package= is equivalent.
Reader and synthesizer options restart the affected process when it
is running; otherwise they take effect on the next start.
If startup fails, check =*Messages*=: the error names the missing
SoundFont, FluidSynth, Cargo, piano-keys, or permission problem.

* Troubleshooting
- *No sound*: make sure the key is in =piano-keys= (case does not
  matter), the =*piano*= buffer is selected, and the saved
  =piano-device= is the keyboard you are using.  =M-x piano-select-device= picks and saves a stable
  device path.  =M-x piano-test-note= tests the synthesizer alone.
- *Missing dependency*: startup errors name the missing FluidSynth,
  SoundFont, Cargo, or =piano-keys= binary.  See the Dependencies
  section above.
- *Reader or synth exited*: the reason is shown in =*Messages*=;
  detailed stderr is in =*piano-keys-errors*= or
  =*piano-fluidsynth-errors*=.
